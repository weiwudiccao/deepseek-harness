# Agent Note: 企福个人云端工作目录范围

Status: implemented

[English](2026-09-03-qifu-personal-cloud-catalog-scope.md) | 中文

## Problem

员工侧边栏把云端目录返回的所有 Work Item 平铺成一份云端工作列表。由于 Employee 角色可以读取企业知识源，OA 回填还会把每个已启用企业知识源投影进每名员工的私有目录。共享知识、个人对话、设计、文件和明确发布的内容因此被展示成同类员工工作；源记录读取权限变化后，保留的投影也可能继续显示。

## Decision

云端工作只列出员工私有的 Conversation、Session、Presentation 和 File 条目。OA 不再在个人目录回填时创建 Knowledge Work Item，从默认及按类型查询结果中排除不支持的类型，并在返回 Existing OA 投影前重新校验当前员工对源记录的读取权限。已有知识元数据继续保留，不执行删除。

桌面客户端独立采用相同的个人类型白名单，并按会话、设计和文件分组。企业知识条目既不出现在云端工作中，也不进入功能区域。授权后的知识继续通过其所属 OA 检索和权限机制提供，不会成为导航条目。

## Alternatives considered

**把企业知识移入功能区域。** 功能表示员工获权使用的应用和动作，不是数据源。移动知识条目会保留错误分类，并可能把大量来源记录暴露为应用导航。

**删除已有 Knowledge Work Item。** 展示修正不需要删除，缺少迁移或留存决策时清除元数据会破坏可恢复性。接口与客户端白名单会使这些记录停止展示，同时保留回退能力。

**只在桌面客户端过滤。** 旧客户端和直接 API 使用方仍会收到混合目录，源权限撤销后的列表元数据也可能继续可见。OA 响应拥有权威范围，客户端白名单提供纵深防护。

## Consequences

员工按内容类型查看个人云端工作，共享企业知识不会占用侧边栏，也不会显示为功能。保留的 Existing OA 投影未通过当前源权限检查时，列表数量可能少于请求页大小；游标仍会跨过已扫描记录。知识检索继续由 Knowledge Source 授权路径控制，不删除任何源内容或保留的 Work Item。
