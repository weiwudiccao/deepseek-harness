# Agent Note: 企福员工功能、云端工作与本机内容界面

Status: proposed

[English](2026-09-02-qifu-employee-work-surface.md) | 中文

## Problem

企福 AI 智脑客户端需要在同一个侧边栏中提供三种不同性质的入口：由 OA 权限决定的功能、保存在企业基础设施中的云端工作，以及保存在员工电脑中的本机内容。三类入口目前没有统一的身份、授权、资源目录和数据流转约定，界面名称也无法准确说明内容实际位于员工电脑还是服务器。

正式 OA 已保存数字员工对话、消息、附件索引、PPT 项目、PPT 版本、知识源和账号记忆。2026-09-02 的只读核验观察到 403 个 AI 对话、4347 条消息、25 个 PPT 项目、36 个 PPT 版本、58 条附件索引、7 个知识源、5 个账号记忆档案和 4 条记忆；这些记录属于不同业务模块，不能通过复制到一个通用表来获得一致性。

正式 OA 的“智脑中心”Workspace 是公开 Workspace。`ZKKG AI User` 对 AI 对话、消息、agent 运行记录和附件索引拥有读取、报表与导出权限，而这些 DocType 没有对应的记录级查询条件。员工业务 API 会按 `actor_user` 过滤，但 Desk 列表、报表、导出、文件和其他通用 Frappe 入口仍需要统一的所有者权限约定。

认证网关按照 OA User id 为每名员工启动独立服务器 DSH 进程，并为每名员工设置独立 `HOME` 与 `DSH_HOME`。这项[员工运行时隔离](../../implemented/feature/2026-09-01-employee-runtime-isolation-and-identity.zh.md)保护 DSH 会话、设置、凭据和浏览器 Cookie，但工作目录仍位于服务器，不能代表员工电脑的本机工作区。

账号记忆实现固定服务数字员工 `b1`，默认启用读取和自动提取，并把达到阈值的对话候选直接保存为 Active。员工身份、员工工作画像、个人长期记忆、客户画像和项目知识具有不同的用途、所有者和授权规则，需要分别管理。

## Proposal

客户端采用“统一入口、三个数据域、一个个性化层、一条显式发布通道”的产品和技术结构。侧边栏依次显示“功能”“云端工作”“本机内容”；身份与权限始终生效，员工工作画像和个人记忆按员工选择注入三个区域中的模型请求。

“功能”由正式 OA 返回的员工能力清单驱动。“云端工作”提供员工私有的企业资源目录，并引用已有业务 DocType 的权威记录。“本机内容”由桌面端本地运行时访问真实本机目录，默认不向企福云端复制会话或文件。员工通过“发布到云端”或“下载为本机副本”显式跨越两个数据域。

企福专属实现放在独立产品插件和部署 Overlay 中；DeepSeek Harness 上游包只承载通用 slot、服务接口和运行时扩展点。该结构把后续上游升级的冲突限制在少量通用接口，避免在每次升级时重新合并整套企福业务逻辑。

首个正式切片落地员工私有的纵向链路：仅桌面端注册员工身份和工作界面插件、由 OA 生成权限功能清单、私有默认云端工作区与统一 Work Item 目录、按员工隔离的云端和本机运行时、明确发布和版本化下载单个本机文件或单个本机会话快照、默认关闭的四项授权、记忆审核与忘记操作，以及每轮首个模型步骤中的持久画像/记忆上下文快照。OA 权限钩子覆盖员工私有 AI 记录和新增工作界面记录；网关在打开功能前重新校验权限；桌面预加载层只暴露接口白名单中的操作。

本方案仍保留尚未进入该切片的能力：团队工作区 ACL、异步恶意文件扫描与对象存储、严格本机模式、运行时空闲回收和可观测性目标，以及完成签名和真机验收的 Windows 分发。不能因为侧边栏入口或授权开关已经出现，就把这些能力视为完成。

## Scope and invariants

| 主题 | 提议约束 |
|---|---|
| 功能 | 正式 OA 是可见性和可执行性的真源；员工不能关闭或扩大自己的权限。 |
| 云端工作 | 员工内容默认私有；每个资源保留自己的业务真源，云端目录只保存统一索引和关系。 |
| 本机内容 | 本机会话和文件默认只保存在当前设备；任何企福云端复制都需要员工对一个明确对象发起操作。 |
| 身份 | 网关从已认证会话推导 User 与 Employee；客户端提交的账号字段永远不作为授权事实。 |
| 个性化 | 权限判断不受个性化开关影响；模型读取画像、读取记忆和写入记忆分别授权。 |
| 传输 | 发布和下载创建有来源、有版本的副本；跨域操作绝不静默覆盖源对象。 |
| 模型流量 | “不保存到企福云端”不代表“不发送给模型”；界面必须在请求前准确说明模型数据路径。 |

本提案不在第一版提供实时多人协作、后台双向文件同步、会话 CRDT 合并、企业网盘替代品或跨企业资源共享。团队共享空间可以复用相同访问控制模型，但必须在员工私有空间通过验收后独立启用。

## Product layout

### Sidebar order

侧边栏在“新会话”下方按照固定顺序显示三个一级折叠组。账号菜单继续位于侧边栏底部，员工点击姓名区域后才显示设置。

| 分组 | 默认状态 | 子项 | 空状态 |
|---|---|---|---|
| 功能 | 展开 | 当前员工可使用的 App 列表 | “当前账号暂无可用功能” |
| 云端工作 | 展开 | 云端工作区、最近会话、设计、文件和知识入口 | “暂无云端内容” |
| 本机内容 | 展开 | 本机工作区、最近本机会话和已下载副本 | “选择一个本机文件夹开始工作” |

三个组的折叠状态按照“员工账号＋设备”保存在本机界面设置中。折叠状态不上传到 OA，也不影响权限和内容存在性。

### Apps layout contract

“功能”组采用参考图中 Apps 的排板语言：一级组标题使用四宫格图标、文字和右侧展开箭头；子项使用单列紧凑列表，不使用大卡片或多列宫格；每项由彩色方形图标和单行名称组成；当前项使用整行圆角背景高亮。

| 元素 | 初始设计 token | 行为 |
|---|---|---|
| Group row | 高度 40 px，左右内边距 12 px | 整行可点击；箭头表达展开状态；提供 `aria-expanded`。 |
| App row | 高度 36 px，左侧缩进 32 px | 单击打开主内容区域；键盘上下键在可见 App 间移动。 |
| App icon | 20 × 20 px，圆角 6 px | 使用受控图标键和主题色，不加载后台提供的任意远程图片。 |
| App label | 单行、溢出省略 | 悬停提示完整名称；禁止用颜色单独表达状态。 |
| Selected row | 8 px 圆角、主题选中背景 | 同时保留文字对比度和焦点环；深色与浅色主题共用语义 token。 |
| Attention badge | 可选、位于行尾 | 只显示员工有权读取的数据计数；零值不显示。 |

后台能力清单提供 `feature_code`、本地化名称键、图标键、主题色键、路由、显示顺序、所需动作和可选角标来源。客户端只接受已注册的图标与路由类型，不执行后台返回的 HTML、脚本或任意 URL。

未经授权的 App 不出现在列表中，也不以禁用灰色项泄露模块存在性。权限加载失败时，客户端显示可重试错误，不回退到完整静态 App 清单。管理员关闭的 App 与员工无权使用的 App 在普通员工界面中使用相同的“不出现”结果。

功能搜索只搜索已授权的清单。员工可以把已授权 App 固定到组内顶部；固定记录保存在员工设置中，但后台 `display_order` 仍决定未固定项目顺序，权限撤销会立即移除对应固定记录。

### Navigation and state

每个 App 使用稳定 `feature_code` 作为界面身份，显示名称变化不改变收藏、角标或深链接。内部页面在主内容区域打开；数字员工类 App 可以创建或恢复一个带 `feature_code` 和 `digital_employee` 的会话；外部链接只允许后台登记的 HTTPS 域名并在打开前明确提示。

加载态使用与真实行数无关的三行骨架，避免泄露权限数量。空态、失败态和权限撤销态分别呈现；客户端收到新的 `capability_revision` 后关闭已失效页面、清除其缓存并说明权限已变化。

## Identity and feature authorization

### Authorization source and bootstrap

同源网关提供版本化 `GET /qifu/v1/bootstrap`。网关从当前 HttpOnly 会话取得 OA Cookie，向正式 OA 查询员工身份和能力，返回最小身份、允许功能、允许动作、个性化状态摘要和版本信息；网关不保存登录密码。

| 字段 | 含义 |
|---|---|
| `contract_version` | 客户端协议版本；未知主版本快速失败。 |
| `employee` | 员工 id、显示姓名、岗位名称和可选头像键。 |
| `capability_revision` | 角色、User Permission、功能配置或 Agent Profile 变化后递增的权限版本。 |
| `features` | 已过滤的 App 清单；每项包含代码、名称键、图标键、路由、顺序与动作。 |
| `data_scopes` | 本人、部门、指定员工、指定项目等服务端数据范围。 |
| `personalization` | 画像读取、记忆读取和记忆写入的当前选择，不包含记忆正文。 |

OA Role、User Permission、Employee、Department、Agent Profile 的部门/员工绑定、Agent Profile 允许工具、知识范围及 `ZKKG AI Client Feature` 配置共同生成能力清单。系统管理员身份不自动获得员工私有内容；管理配置权、审计元数据权和紧急内容访问权分别授权。

能力结果以 60 秒为最长缓存时间，并由 `capability_revision` 主动失效。撤销权限后的下一次 API 或工具调用必须立即拒绝；客户端刷新只负责更新展示，不是撤权生效条件。

### Enforcement points

服务端为 Conversation、Message、Agent Run、Attachment Index、Cloud Workspace、Work Item、Session Binding、Sync Transfer 和相关 File 增加 `permission_query_conditions` 与 `has_permission`。所有列表、详情、报表、导出、搜索、文件下载、WebSocket 订阅和后台任务在进入业务逻辑前解析同一所有者和数据范围策略。

工具 schema 只向模型展示当前员工允许调用的工具。工具执行器在每次调用时再次验证动作、目标记录和 `capability_revision`，因此旧会话、旧提示词或手工 HTTP 请求不能绕过最新授权。

员工私人内容的默认规则是 `owner_user == frappe.session.user`。团队资源要求显式 Workspace ACL。管理人员需要查看员工内容时使用有原因、有时限、有审批和完整审计的紧急访问流程，普通 `ZKKG AI Manager` 只管理配置与运行健康。

## Cloud work

### Federated catalog

云端工作是统一资源目录，不是统一正文表。每个业务模块继续拥有自己的记录和状态机，`ZKKG AI Work Item` 通过受控 Dynamic Link 指向原始记录，并保存列表投影、所有者、工作区、来源、版本和安全分类。

| 资源类型 | 权威内容 | 云端工作投影 |
|---|---|---|
| 数字员工对话 | `ZKKG AI Conversation` 与 `ZKKG AI Message` | 标题、数字员工、最近活动、摘要和权限状态 |
| Harness 会话 | 版本化 DSH 事件日志 | 标题、运行环境、会话格式、恢复状态和标准 transcript 投影 |
| PPT 与设计 | Presentation Project、Version、Slide 与 Source | 项目状态、当前版本、预览和交付文件 |
| 文件与附件 | 私有对象存储、Frappe File 与 Attachment Index | 文件名、类型、大小、摘要、扫描状态和来源关系 |
| 知识内容 | Knowledge Source、Chunk、Entity 与 Relation | 来源状态、索引版本和授权范围 |

每名员工首次访问时惰性创建一个私有默认工作区。第一版只允许员工拥有自己的私人工作区；数据模型保留 `visibility` 和 ACL 表，以便后续增加部门或项目共享，而不改变私人记录的所有者约定。

Work Item 是可重建索引，不保存业务正文。原始记录更新通过 DocType 事件刷新投影；失败进入重试队列。列表读取先按 Workspace 和员工权限过滤，再读取投影，不允许先做全文或向量检索后再过滤结果。

### Session persistence

云端 Harness 会话保留版本化原始事件日志和标准化 transcript 两层。原始事件日志负责准确恢复、工具状态和审计；标准化 transcript 负责跨版本列表、搜索和用户导出。两者通过 Session Binding、事件摘要和最后序列号关联，不作为两个可独立修改的真源。

活动日志继续使用[每会话 JSONL 持久化](../../../../packages/session/session-persistence-jsonl/README.zh.md)。员工专属服务器数据盘保存热日志；加密检查点复制到私有对象存储。Session Binding 记录 Harness 版本、Session 格式版本、最后提交序列号、日志摘要、对象版本和恢复状态。任何升级必须先验证现有格式读取或执行显式迁移。

OA 数字员工对话不强制转换为 DSH 事件日志。它们保留现有 Conversation/Message 真源，并通过同一个 Work Item 和 Session Binding 目录出现在云端工作中。

### Objects, search, and lineage

大文件和生成产物进入私有对象存储，数据库只保存元数据、内容摘要、对象键、版本和引用。对象键不返回普通客户端；下载使用员工权限校验后生成的短时签名 URL。服务端加密、恶意文件扫描和 MIME 内容探测完成前，Work Item 不进入 Ready。

内容摘要用于完整性与幂等，不作为授权凭据。去重限定在同一企业和相同安全分类中，并使用企业范围 HMAC 摘要，避免跨企业内容存在性侧信道。

会话、来源文件、设计版本、生成产物和记忆之间通过不可变关系记录建立来源链。搜索索引和向量是派生数据；权限收窄、源内容删除或记忆忘记后，派生索引必须进入失效队列并在规定时间内清除。

## Local content

### Local runtime

桌面应用同时拥有本机 loopback DSH 运行时和云端网关连接。本机内容页面只连接本机运行时；云端工作页面只连接云端运行时。标题栏和会话头持续显示“本机”或“云端”，不能依据当前路由隐式推断运行位置。

本机运行时使用员工账号与设备 id 派生的数据目录。macOS 使用 Application Support 下的企福目录，Windows 使用 LocalAppData 下的企福目录；目录名使用不可逆员工键。加密主密钥只存储在 macOS Keychain 或 Windows DPAPI，OA 密码、OA Cookie 和云端长期令牌不写入本机会话日志。

本机工作区必须是员工通过原生目录选择器明确选择的真实目录。[Workspace 注册表](../../../../packages/workspace/workspace/README.zh.md)负责目录与会话分组，但操作系统沙箱和 DSH 权限策略仍决定可读写范围。不同员工在同一设备上拥有不同 DSH_HOME、Workspace 注册表、会话、附件、设置和凭据。

退出账号会撤销云端会话、清除短期令牌和临时画像缓存，但默认保留加密本机内容，供同一员工再次登录。设置提供“同时删除此设备上的本机内容”，并在删除前显示目录、对象数、预计空间和不可恢复警告。

### Network disclosure

“本机保存”只描述企福的持久化位置。当本机会话使用云端模型、联网搜索、OA 工具或其他远程服务时，相关请求内容仍会离开设备。发送按钮附近显示当前模型数据路径；首次使用一种新数据路径时展示一次简短说明。

严格本地模式只能选择本地模型和本地工具，并禁止云端画像、云端记忆、联网搜索和 OA 写操作。普通本机模式允许员工选择性读取云端画像或调用企业功能，但不会因此上传完整 transcript、工作区目录或未选择文件。

本机调用 OA 创建审批、任务或其他企业记录属于员工明确发起的业务写入，不归类为“本机内容同步”。确认界面必须展示将创建的记录类型和目标系统。

## Explicit transfer

### Transfer contract

界面避免使用含义不清的“自动同步”。`发布到云端` 表示从一个本机会话或文件创建云端版本；`下载为本机副本` 表示从一个云端对象创建本机副本；`刷新云端信息` 只读取远程元数据；`临时使用画像与记忆` 只读取授权上下文并使用短期缓存。

发布流程按照固定顺序执行：员工选择一个对象和包含范围；客户端生成可审查清单并移除本机绝对路径；员工确认；客户端计算摘要并分片上传；服务端验证能力、配额、MIME、恶意内容和敏感策略；服务端原子提交业务记录、Work Item、来源关系和审计记录。

会话发布默认包含可见 transcript、选中的附件、选中的交付产物和必要来源关系。它不包含环境变量、凭据、隐藏推理、本机绝对路径、未选择工作区文件或其他会话。员工可以在确认页逐项取消附件和产物。

| 传输状态 | 含义 |
|---|---|
| Initiated | 服务端已验证当前能力并返回上传 id、分片策略和过期时间。 |
| Uploading | 客户端上传缺失分片；重试使用同一个传输 id 和分片摘要。 |
| Scanning | 服务端验证完整摘要、文件类型、恶意内容和敏感策略。 |
| Ready | 所有对象已就绪，但云端业务记录尚未可见。 |
| Committed | 元数据、对象引用、Work Item、来源关系和审计已原子发布。 |
| Failed or Cancelled | 临时对象在 24 小时后回收；失败不会产生半成品 Work Item。 |

写操作要求 `Idempotency-Key`。相同员工、相同操作和相同请求摘要返回同一结果；相同键携带不同摘要返回冲突。服务端不信任客户端提供的 owner、company、employee 或权限范围。

### Versions and conflicts

文件发布以内容摘要创建新版本。相同摘要可以复用当前员工已有版本；不同摘要永远不覆盖旧版本。会话发布冻结一个来源序列号；发布后本机继续对话和云端继续对话形成两个 fork，并在界面显示共同来源。

从云端下载后修改并再次发布时，客户端提交 `base_version`。服务端发现云端已有更新后拒绝覆盖，并提供“另存为新版本”或“创建副本”；第一版不提供自动文本、二进制或会话合并。

## Personalization and memory

### Data classes

| 数据类型 | 所有者与来源 | 模型使用方式 |
|---|---|---|
| 身份与权限事实 | OA User、Employee、Department、Role 与 User Permission | 授权和审计始终使用；模型只取得任务必需的最小字段。 |
| 员工工作画像 | OA 管理字段和员工可编辑偏好 | 员工选择后按当前功能和任务注入。 |
| 个人长期记忆 | 员工明确记录或经确认的对话候选 | 员工选择后按相关性注入。 |
| 项目知识 | 当前 Workspace 授权资源 | 员工在会话或项目中选择，不能被个人记忆开关隐式扩大。 |
| 客户画像 | 客户业务模块 | 仅在员工有客户权限且当前任务明确涉及客户时使用。 |

员工身份和权限不设关闭开关。设置提供四个独立选择：“使用我的工作画像辅助回答”“允许读取我的云端记忆”“允许从云端对话提取新记忆”“在本机会话中临时读取云端画像和记忆”。每项保存同意版本、时间、设备、策略版本和撤回时间。

读取选择不授权写入，云端会话发布也不自动授权记忆提取。员工撤回读取后，下一次模型请求不得包含相关上下文；员工撤回写入后，系统停止生成候选，但保留员工尚未删除的既有记忆。

### Memory lifecycle and context evidence

自动提取产生 Proposed 候选，不直接产生 Active 记忆。员工确认后进入 Confirmed/Active；员工明确说“记住”可以直接创建 Active；更正产生新版本并标记被替代项；“忘记”立即停止检索并触发派生缓存与向量清理。

记忆准入采用允许类别、敏感信息检测、来源证据、置信度和有效期共同判断。密码、令牌、Cookie、银行卡、身份证、医疗信息、生物特征和完整薪资数据不得进入个人记忆；凭据只能进入现有凭据服务或操作系统安全存储。

每次模型请求创建 Context Snapshot，保存所用画像/记忆/项目资料 id、策略版本、能力版本、来源摘要和精确加密渲染内容。会话事件记录 Snapshot id 与摘要，满足模型可见内容可重建要求；Agent Run 不再复制完整上下文到多个 JSON 字段。

员工可以在会话详情查看“本次使用的资料”，但模型无需在正文中解释内部检索过程。删除记忆后，未来请求和搜索索引立即失效；历史会话中的已使用上下文按照企业留存策略保留、脱敏或加密擦除，并留下不含正文的审计摘要。

## Data model

| 记录 | 关键字段 | 所有权与用途 |
|---|---|---|
| `ZKKG AI Client Feature` | feature_code、label_key、icon_key、route_type、route、display_order、enabled、actions | 管理可发布 App；角色、部门、员工和 Agent Profile 子表定义候选范围。 |
| `ZKKG AI Cloud Workspace` | workspace_id、company、owner_user、owner_employee、visibility、retention_policy | 员工私人云端空间；后续通过独立 ACL 子表支持团队空间。 |
| `ZKKG AI Work Item` | item_id、workspace、resource_doctype、resource_name、kind、origin、title、version、classification、status | 可重建资源目录和列表投影，不保存原始正文。 |
| `ZKKG AI Session Binding` | binding_id、workspace、owner_user、oa_conversation、dsh_session_id、runtime、harness_version、format_version、last_seq、digest | 连接 OA 对话、DSH 日志、标准 transcript 和云端目录。 |
| `ZKKG AI Sync Transfer` | transfer_id、owner_user、device_id、direction、source_id、base_version、digest、state、idempotency_key、expires_at | 拥有上传、下载、重试、冲突和回收状态。 |
| `ZKKG AI Work Relation` | relation_id、from_item、to_item、relation_type、source_version、digest | 保存来源、生成、附件、版本和 fork 关系。 |
| `ZKKG AI Personalization Consent` | owner_user、profile_read、memory_read、memory_write、local_context_read、policy_version、granted_at、revoked_at | 保存四项选择及审计事实。 |
| 现有 Account Memory 与 Context Snapshot | actor_user、scope、category、value、source、status、expiry、snapshot payload、policy revision | 扩展现有记忆，不另建竞争真源。 |

所有员工内容记录显式保存 `owner_user` 和 `company`；Employee 用于业务展示和组织查询，不作为永久登录身份。面向客户端的 id 使用随机不透明标识，不把邮箱、手机号、User id、Employee id 或服务器路径编码进 id。

数据库约束保证 Work Item 的资源引用唯一、Session Binding 的运行时会话唯一、传输幂等键在员工和操作范围唯一、版本号在资源范围单调。后台任务只能使用任务记录中冻结的 owner 和能力摘要，不能以 Administrator 的全局视角重新选择数据。

## API contracts

所有接口由同源网关暴露 `/qifu/v1` 主版本。网关把浏览器会话或桌面设备会话交换成短期内部凭据，并将权威 OA 身份放入服务端请求上下文；正文中的 owner 字段只作为显示数据处理。

| 方法与路径 | 用途 | 必需的鉴权 |
|---|---|---|
| `GET /bootstrap` | 返回员工身份、功能、数据范围、个性化摘要和版本 | 已登录；禁止缓存；能力响应签名或同源完整性保护。 |
| `GET /cloud/workspaces` | 列出员工可访问的云端工作区 | owner/ACL 查询条件。 |
| `GET /cloud/items` | 按工作区、类型和游标列出 Work Item | 先权限过滤，再搜索与分页。 |
| `GET /cloud/items/{id}` | 返回一种资源的安全详情投影 | Work Item 与原始记录双重权限。 |
| `POST /cloud/sessions` | 创建云端 Harness 会话和绑定 | 功能动作、Workspace 写权限和幂等键。 |
| `POST /transfers` | 初始化发布或下载 | 来源权限、目标权限、配额、设备状态和能力版本。 |
| `PUT /transfers/{id}/parts/{part}` | 上传一个分片 | 传输所有者、摘要、大小和过期时间。 |
| `POST /transfers/{id}/commit` | 扫描并原子提交云端版本 | 全量摘要、策略扫描、幂等和事务提交。 |
| `GET /personalization` | 返回设置和可审查画像/记忆元数据 | 只允许当前员工；敏感字段脱敏。 |
| `PATCH /personalization` | 更新四项选择或画像偏好 | 同意版本、CSRF、审计和即时失效。 |
| `GET/PATCH/DELETE /memories/{id}` | 查看、更正或忘记一条个人记忆 | 当前员工所有权、版本冲突和派生数据失效。 |

列表使用稳定游标，不使用无界 `limit_page_length`。写接口返回稳定错误码，包括 `CAPABILITY_CHANGED`、`PERMISSION_DENIED`、`IDEMPOTENCY_CONFLICT`、`BASE_VERSION_CHANGED`、`CONTENT_REJECTED` 和 `TRANSFER_EXPIRED`；客户端根据错误码恢复，不解析中文错误文本。

WebSocket 与 SSE 建连时验证会话，订阅时验证资源，每次权限修订后重新验证。后台完成事件只向当前员工和明确 ACL 成员发布，不使用可猜测房间名。

## Deployment topology and upgrade isolation

正式 OA 的 `zkkg_ai` 应用拥有 DocType、授权策略、云端目录、个性化、传输元数据和业务资源适配器。认证网关拥有 OA 会话交换、证书锁定入口、员工云端运行时选择、短期设备令牌、分片传输代理和 WebSocket 路由。私有对象存储拥有加密事件检查点和文件字节。

桌面应用拥有本机运行时生命周期、原生目录选择器、Keychain/DPAPI、本机数据根、发布预览和网络路径提示。DeepSeek Harness 产品插件拥有功能清单消费方、工具过滤器、云端目录 UI、个性化上下文提供方和传输客户端。

受控 fork 把产品专属桌面端和网关源码保存在 `qifu/` 版本化部署 Overlay 中，并锁定经过验收的 DeepSeek Harness 提交。产品插件使用 `/qifu/v1` 稳定协议，不直接导入 OA 私有 Python 实现。后续若把 Overlay 迁入独立私有仓库，该仓库必须保留相同的提交锁定和发布门禁。上游若缺少通用 slot 或服务接口，只向上游维护最小、无企福业务名词的扩展改动。

升级门禁包括：在独立 worktree 比较上游、备份当前代码与数据、运行插件兼容测试、读取全部受支持 Session 格式、完成 macOS 与 Windows 真机验收、canary 员工验证、保留可启动的旧版本和数据格式回滚路径。任何迁移写入新格式后，旧版本必须仍可只读导出，或切换前明确完成不可逆迁移批准。

## Migration and rollout

| 阶段 | 预计工作量 | 工作内容 | 退出条件 |
|---|---:|---|---|
| 0. 员工内容权限 | 4–6 工程日 | 增加记录级查询与详情权限；关闭普通员工报表/导出旁路；保护 File、搜索和实时订阅；建立两员工测试数据。 | 员工 A 不能从任何通用或业务入口观察员工 B 的存在或内容；撤权立即生效。 |
| 1. 功能与云端目录 | 7–10 工程日 | 建立 Client Feature、bootstrap、Cloud Workspace、Work Item、Session Binding 和既有内容适配器；交付 Apps 样式功能列表。 | 功能显示与服务端动作一致；既有对话、PPT、附件和知识源通过索引出现且未复制正文。 |
| 2. 本机运行时 | 10–15 工程日 | 桌面端启动本机 DSH、建立员工＋设备数据根、原生目录选择、加密密钥、运行位置标识和严格本地模式。 | 断网时本机会话和文件操作可用；两名员工不能读取对方本机数据；云端无新增内容记录。 |
| 3. 显式发布 | 8–12 工程日 | 建立传输状态机、预览、分片、扫描、幂等、版本、来源关系、下载副本和冲突处理。 | 只上传所选对象；重试不重复；冲突不覆盖；失败不留下可见半成品。 |
| 4. 画像与记忆 | 6–9 工程日 | 拆分四项选择、候选确认、Context Snapshot、派生数据失效、使用资料 UI 和历史留存策略。 | 关闭后下一请求不使用相关上下文；忘记后检索与索引失效；模型输入可按审计重建。 |

Phase 0 必须先完成，其他阶段不得用 UI 隐藏替代权限修复。Phase 1 通过惰性创建和批量回填接入现有数据：脚本按 owner 建立默认 Workspace，为现有 Conversation、Presentation、Attachment 和 Knowledge 记录创建幂等 Work Item；正文不移动，原有 URL 和业务状态机保持有效。

现有账号记忆在迁移时标记 `consent_state = Review Required`。系统保留原记录但暂停自动注入和自动提取，员工首次打开个性化设置后逐项选择；明确选择前不推断同意。现有 Context Snapshot 和审计记录保持只读。

现有服务器员工 DSH_HOME 通过网关持有的员工映射登记为 Cloud Session Binding；系统不尝试反推不可逆目录键。缺少可靠映射的目录进入隔离清单，由管理员只读核验后关联或归档。

每个 Phase 先进入独立测试环境，使用脱敏数据完成 API、权限、迁移、浏览器和桌面验收；经用户确认后才进入正式发布流程。正式迁移先备份数据库、对象清单和服务器 DSH_HOME，再执行可重复、可中断、带检查点的批次任务。

## Operational readiness

网关和 OA 记录结构化指标：bootstrap 延迟与失败率、能力修订传播时间、权限拒绝数、每员工云端运行时数量、会话持久化延迟、传输吞吐与失败、扫描拒绝、Context Snapshot 创建与失效、对象存储容量。日志只记录 trace id、员工不可逆键、资源不透明 id、错误码和时序，不记录密码、Cookie、令牌、完整提示词或文件正文。

建议初始目标为：权限撤销在 60 秒内传播且所有写操作即时验证；bootstrap 第 95 百分位低于 500 ms；同一区域云端会话恢复第 95 百分位低于 5 秒；已提交云端元数据 RPO 不超过 15 分钟、RTO 不超过 4 小时。目标通过配置和运行手册管理，不硬编码进插件。

正式 OA 数据库使用现有备份体系；对象存储启用版本控制、生命周期、服务端 KMS 加密和跨故障域副本；员工云端 DSH_HOME 生成加密检查点。每季度执行一次抽样恢复，验证 Workspace、Session Binding、日志、文件版本和权限关系共同恢复。

本机内容不承诺企业云端恢复。设置显示本机数据目录、占用空间、最后本机备份时间和已发布状态，并允许员工导出加密备份。设备丢失后，管理员可以撤销设备云端令牌，但不能声称已远程删除离线磁盘内容。

TLS 证书锁定支持同时配置当前与下一枚公钥指纹，先发布双指纹客户端，再轮换服务端证书，最后移除旧指纹。客户端拒绝未知证书，证书轮换不要求把私钥或固定令牌放入仓库。

## Acceptance criteria

### Feature area

- “功能”组在桌面宽度和折叠侧栏下均使用单列 Apps 样式，支持展开、键盘导航、焦点环、选中态、完整名称提示和高对比度主题。
- 两个权限不同的员工获得不同 App 列表；无权 App 不出现在搜索、深链接建议、角标订阅或模型工具 schema 中。
- 管理员撤销功能后，旧页面关闭，下一次工具/API 调用拒绝，客户端不依赖重新登录。
- App 顺序、图标和路由只接受后台受控值；恶意图标、脚本、HTML 和未授权外部域名被拒绝。

### Cloud work

- 员工只能列出和打开自己的私人 Workspace、Work Item、原始业务记录、文件和搜索结果。
- 现有 Conversation、Presentation、Attachment 和 Knowledge 内容通过适配器出现，正文哈希与原记录一致且没有竞争副本。
- Harness 会话同时提供可恢复事件日志和标准 transcript；升级测试可以读取全部受支持格式。
- 删除或收窄权限后，列表、全文索引、向量索引、签名 URL 和实时订阅在规定时间内全部失效。

### Local content and transfer

- 新建本机会话、注册本机目录和生成本机文件不会创建 Cloud Workspace、Work Item、Sync Transfer 或云端附件。
- 同一设备的两个员工拥有不同加密数据根；退出和重新登录不会把一个员工的本机会话展示给另一个员工。
- 发布预览准确列出 transcript、附件和产物；抓包与服务端审计证明未选择对象没有上传。
- 网络中断、重复提交和进程重启保持传输幂等；基础版本冲突永远不覆盖既有云端版本。
- 界面准确区分企福持久化和模型网络传输；严格本地模式无远程模型、搜索、画像、记忆或 OA 调用。

### Personalization and memory

- 身份和权限在所有选择关闭时仍正确执行，模型只收到任务必需的最小身份事实。
- 画像读取、记忆读取、记忆写入和本机临时读取可以独立启用与撤回，服务端记录同意版本和时间。
- 自动提取只创建 Proposed，员工确认或明确“记住”后才产生 Active。
- 每个模型请求关联精确 Context Snapshot；Agent Run 和业务 JSON 不复制无管理的完整个性化正文。
- “忘记”立即停止未来检索，并按留存策略清理缓存、全文/向量索引和可擦除历史快照正文。

### Security, operations, and upgrade

- 员工 A 无法通过 REST、Desk、报表、导出、文件 URL、搜索、WebSocket、后台任务或可猜测 id 获得员工 B 的记录。
- 配置管理员默认看不到员工内容；紧急访问要求原因、审批、时限，并产生员工、管理员和审计方可追踪的记录。
- 日志、指标、崩溃报告、客户端存储和仓库中不存在密码、Cookie、令牌、私钥或完整敏感正文。
- 数据库、对象、Session 日志和权限关系的恢复演练满足声明的 RPO/RTO，并验证恢复后仍保持员工隔离。
- 独立 Overlay 在目标上游提交上通过插件测试、文档检查、macOS 与 Windows 真机流程和 canary 员工验收后才允许升级。

## Alternatives considered

**把全部 OA 数据复制进一套 Cloud Work 表。** 该方案会建立多个正文真源，破坏 PPT、知识库和数字员工已有状态机，并使权限、版本和删除行为分叉。统一索引与受控适配器提供一致入口，同时保留各业务模块的所有权。

**继续使用服务器工作目录并把它命名为“本机内容”。** 浏览器和桌面包装层无法让服务器进程直接获得员工电脑的真实文件系统语义，这个命名会对隐私和数据位置作出错误承诺。本机内容需要设备上的本地运行时。

**第一版提供后台双向同步。** 自动同步会扩大上传范围、制造覆盖冲突，并使员工难以判断哪个版本是权威版本。显式发布、下载副本和 fork 语义提供可审计的数据移动，后续可以在独立需求中评估协作同步。

**用一个总开关控制账号画像和记忆。** 读取既有信息、从对话生成新记忆和在本机请求远程信息具有不同的数据方向和风险。四项独立选择允许员工给出具体同意，并保持权限判断不可关闭。

**继续把企福逻辑直接写入上游核心包。** 大量产品字段、OA API 和 UI 规则会放大每次上游升级的合并范围。产品插件与受控 `qifu/` Overlay 保留企福交付速度，并把上游改动限制为可复用扩展点。

## Risks

- 每名活跃云端员工一个 Node 进程会消耗内存和端口；网关需要并发上限、空闲回收、启动合并和容量指标，达到阈值后再引入共享 worker 池。
- 用户可能把“本机保存”理解为完全离线；持续位置标识、模型路径提示和严格本地模式必须与本机运行时一起交付。
- DSH 预发布 Session 格式可能变化；Session Binding、格式读取测试、标准 transcript 和升级前迁移是云端长期可读性的必要成本。
- 通用 Work Item 适配器可能与业务记录权限漂移；每个资源类型需要权限一致性测试，适配器失败必须隐藏投影并告警，不能返回陈旧内容。
- 忘记记忆与历史可重建要求存在张力；企业留存策略必须在上线前确定可保留、需脱敏和需加密擦除的类别，并在界面准确说明结果。
